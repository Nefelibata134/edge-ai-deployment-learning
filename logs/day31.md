## 系统数据流

```text
IMX219 / file
    -> GStreamer frame source
    -> bounded capture queue
    -> YOLOX TensorRT detector
    -> Detection[]
    -> ByteTrack adapter
    -> Track[]
    -> analytics statistics
    -> bounded annotated-video queue
    -> background draw and MP4 encode
```

检测器只负责回答“当前帧中有什么目标”，跟踪器结合历史状态回答“这些目标分别是谁”。`Track` 在检测框之外增加持久 `track_id` 和轨迹状态，为后续 ROI、越线、停留时间和事件去重提供基础。

## ByteTrack 核心

- 引入 FoundationVision ByteTrack 的 MIT C++ 算法核心，保留独立第三方目录和许可证。
- Kalman Filter 根据历史运动估计目标下一位置。
- LAPJV 对全部轨迹和检测框进行全局一对一匹配，避免多个轨迹抢占同一检测框。
- 第一阶段使用高置信度检测完成主要关联；第二阶段使用低置信度检测挽救被遮挡或检测分数暂时下降的已有轨迹。
- 项目适配层实现 `ITracker`，负责 `Detection` 与上游对象的双向转换，并按类别隔离关联，避免不同类别互相继承轨迹。
- 输入流重新连接或切换时调用 `reset()`，防止新画面继承旧流的 ID、停留时间或事件状态。

## 确定性验证

独立检查程序验证四项行为：

```text
id_continuity=true
low_score_recovery=true
class_isolation=true
reset_clears_state=true
status=PASS
```

亲自修改第二帧检测框的横坐标，从 `x=12` 移至 `x=500` 后，低置信度检测与旧轨迹失去空间关联，程序按预期返回失败：

```text
low-confidence second association lost the track
expected_failure_exit=1
```

恢复检测框位置后重新通过全部检查，说明测试确实覆盖关联行为，而不是只验证程序能启动。

## IMX219 实时跟踪结果

在 30 帧预热、300 帧正式测量、采集队列容量 2 的条件下：

| 指标 | 结果 |
| --- | ---: |
| 有检测的帧 | 251 |
| 有跟踪结果的帧 | 235 |
| 唯一轨迹 ID | 2 |
| 跟踪 P95 | 0.078 ms |
| 推理 P95 | 13.274 ms |
| 端到端 P95 | 14.020 ms |
| 正式阶段采集丢帧 | 0 |
| 有效 FPS | 30.085 |

连续画面中的目标保持相同 ID；目标消失并超过轨迹缓冲期后，再次出现会创建新 ID。

## 视频输出瓶颈与修复

首版在实时线程中同步执行绘框和 `VideoWriter::write()`。编码速度慢于输入时，主线程被阻塞，采集队列不断丢弃旧帧：

| 输出方式 | 输出队列 | FPS | 采集丢帧 | 采集等待 P95 | 主线程视频操作 P95 | 录像丢帧 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 同步编码 | 无 | 21.590 | 115 | 65.473 ms | 56.137 ms | 0 |
| 异步编码 | 4 | 30.039 | 0 | 0.700 ms | 1.296 ms | 2/300 |
| 异步编码 | 1 | 30.033 | 0 | 0.699 ms | 1.199 ms | 18/300 |

异步实现将帧和轨迹快速复制到独立有界队列，后台线程负责绘框和 MP4 编码。队列满时只丢弃最旧的待写录像帧，不阻塞检测与跟踪。

- 容量 4 时吞吐量相比同步编码提升约 39%，实时采集丢帧从 115 降至 0。
- 容量 1 时实时链路仍维持 30 FPS，但录像丢帧从 2 增至 18，证明背压已被隔离。
- `dropped` 发生在推理前，可能导致模型漏掉短暂目标或事件。
- `output_frames_dropped` 发生在推理和跟踪后，只影响录像连续性，不影响本次实时分析。
- 默认容量选择 4，用少量有界内存吸收短时编码抖动。

## 遇到的问题

- 上游 ByteTrack 构建初次遗漏 `utils.cpp`，导致 IoU 距离和 LAPJV 分配函数链接失败；补齐上游源文件后解决。
- Windows Git 推送多次遇到 TLS 中断，使用完整 Git bundle 将提交传至 Jetson 后由 Jetson 推送。
- 同步标注视频编码将实时 FPS 从约 30 降至 21.59，并导致 115 帧采集丢失；改为后台有界队列后恢复实时性能。
- 录像队列过小会增加输出丢帧，说明“主链路不阻塞”不等于“录像天然完整”，两者必须分别统计。

## 复盘

- 跑通检测模型不是项目终点，持续输入、稳定 ID、背压隔离、指标和故障边界才构成可用的实时系统。
- 第三方算法核心应与项目适配层分离，便于保留许可证、独立测试和后续替换实现。
- 实时系统优先保证分析新鲜度；录像完整性作为独立服务质量指标监控，不能反向拖垮检测和事件判断。
- 平均延迟不足以发现抖动，P95、队列高水位、两类丢帧和统计守恒需要共同观察。
