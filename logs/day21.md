## 指标理解

对每个类别的所有像素进行二分类统计：

- TP：真实为缺陷，预测也为缺陷。
- FP：真实为背景，预测为缺陷。
- FN：真实为缺陷，预测为背景。
- TN：真实和预测均为背景。

由此得到：

```text
Dice      = 2TP / (2TP + FP + FN)
IoU       = TP / (TP + FP + FN)
Precision = TP / (TP + FP)
Recall    = TP / (TP + FN)
```

钢材图片中背景像素远多于缺陷像素，因此不能用 Accuracy 作为核心指标。
如果把大量“真实为空且预测为空”的图片都记为满分，平均结果也会被正常图片
抬高。本项目采用数据集级像素累计指标，并另外统计图片级误报和漏报。

模型原始输出是 logits，需要经过 `sigmoid` 转成 0 到 1 的概率，再根据阈值
得到二值掩码。阈值越高通常越保守，会降低误报，也可能增加漏报。

## 错误分析工具

正式项目新增了以下工程能力：

- 按数据集累计四个类别的 Dice、IoU、Precision 和 Recall。
- 按图片、按类别保存 TP、FP、FN、预测像素和真实像素。
- 统计图片级真阳性、假阳性、假阴性和真阴性。
- 自动选出 best overlap、false positive、false negative、
  mislocalized 和 worst positive 样例。
- 生成四联图：原图、真实掩码、预测掩码和像素错误图。

错误图颜色：

- 绿色：TP，预测正确的缺陷像素。
- 红色：FP，模型多预测的像素。
- 蓝色：FN，模型漏掉的像素。

## 候选模型对比

所有阈值都只在 1,885 张验证图片上选择，测试集继续封存。

| 候选模型 | 轮数 | 最佳阈值 | 验证集 Macro Dice | 结论 |
| --- | ---: | ---: | ---: | --- |
| 随机采样基线 | 5 | 0.05 | 0.2851 | 淘汰 |
| 类别感知采样，power=0.50 | 5 | 0.70 | 0.3846 | 淘汰 |
| 类别感知采样，power=0.75 | 5 | 0.80 | **0.3998** | **入选** |
| 受控采样和增强 | 15 | 0.50 | 0.3206 | 淘汰 |
| 辅助分类头和软门控 | 15 | 0.50 | 0.3292 | 淘汰 |

两个 15 轮候选都提升了常见类别，但类别 1、2 的 Dice 退化为 0。
这说明更长训练和更复杂结构不一定更好，也说明 15 轮足以否决这两条路线，
但不是“所有模型都只需训练 15 轮”的固定规则。

最终保留简单的单头 U-Net + ResNet18、BCE + Dice 和
`sampling_power=0.75`。没有把失败的辅助分类头、软门控和受控采样带入
部署主线。

## 工程决策

本项目的重点是展示完整部署工程：

```text
数据校验与确定性切分
-> PyTorch 训练与模型选择
-> ONNX 导出与数值一致性
-> TensorRT FP32/FP16
-> Triton 推理服务
-> FastAPI、Docker、压测与监控
```

模型质量必须达到可解释、可部署的程度，但项目目标不是依靠集成、伪标签或
复杂比赛技巧追求榜单分数。当前模型已经满足进入部署阶段的条件，后续停止
无依据调参，只有在部署链路完成后仍有明确收益证据时才追加训练。

正式项目仓库继续面向招聘展示，不使用 `DayXX`、学习、练习或打卡式描述。
失败实验只通过模型选择报告和工程决策说明，不把已否决结构留在生产代码中。
