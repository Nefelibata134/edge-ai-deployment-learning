# 项目 3：Jetson + STM32 视觉安全控制原型

记录日期：2026-08-28

计划仓库名：`jetson-stm32-vision-safety-controller`

当前状态：方向、边界和采购方案已确定，尚未创建正式仓库。是否启动、何时
启动以及首版范围由用户按实际需求决定，不绑定 Day 编号。

## 项目定位

项目 3 将项目 2 产生的实时风险事件转换为可验证的物理控制：

- Jetson Orin Nano 运行视觉感知，判断人员是否进入警告区或危险区。
- Jetson CAN 网关把风险等级、目标速度和心跳发送给 STM32。
- STM32 使用 FreeRTOS、安全状态机、PWM 和编码器控制桌面电机。
- STM32 将实际转速、控制状态、急停状态和故障码返回 Jetson。
- Jetson、视觉进程、摄像头或 CAN 失效时，STM32 在限定超时内独立停车。
- 故障恢复后不自动重新启动，必须经过人工复位。

系统使用两级健康信号，不能把“进程存在”误认为“视觉正常”：

1. 项目 2 根据真实帧序号和时间戳发布 `PerceptionStatus`，只有真实视频帧持续
   前进时才标记感知健康。
2. 项目 3 的 Jetson CAN 网关只有在 `PerceptionStatus` 未超时且流代次有效时，
   才向 STM32 发送允许运行的控制心跳。
3. 摄像头无帧、项目 2 卡住、本地事件协议中断或 CAN 心跳超时，STM32 都进入
   `FAULT/STOP`，而不是继续执行最后一次速度命令。

这是桌面级工程验证原型，不宣称达到工业功能安全认证。

## 最终可见效果

```text
IMX219
  -> 项目 2：检测、跟踪、ROI / dwell 风险事件
  -> 版本化本地风险事件协议
  -> 项目 3 Jetson SocketCAN 网关
  -> CAN 总线
  -> STM32 FreeRTOS 控制器
  -> 电机驱动、编码器、信号灯、蜂鸣器、急停
  -> CAN 回传实际转速、状态和故障
```

演示顺序：

1. 无人进入区域时，电机以正常速度运行，绿灯亮。
2. 人员进入警告区时，STM32 将电机降速，黄灯和蜂鸣器启动。
3. 人员进入危险区或停留超时时，STM32 制动电机，红灯亮。
4. 编码器回传实际转速，证明执行机构真实减速或停止，而不只是收到命令。
5. 拔掉 CAN、终止 Jetson 进程或停止视觉帧流，STM32 在心跳超时后独立停车。
6. 通信恢复后保持停止，人工按下复位按钮后才允许重新运行。

## 与项目 2 的边界

项目 2 不会因为项目 3 出现而失去意义。两者对应真实系统中的两个不同层级：

| 边界 | 项目 2：视觉感知与事件系统 | 项目 3：实时控制与失效安全系统 |
| --- | --- | --- |
| 输入 | CSI、RTSP、视频文件 | 版本化风险事件、CAN 反馈、按键和编码器 |
| 核心职责 | 解码、TensorRT 检测、ByteTrack、事件分析、证据留存 | CAN、FreeRTOS、状态机、PWM、测速、急停和故障处理 |
| 输出 | 风险事件、JSONL、截图、录像、运行指标 | 电机动作、状态灯、故障码、实际转速和安全停车 |
| 主要指标 | FPS、P95 延迟、丢帧率、事件准确率、功耗 | CAN 延迟、控制周期、转速误差、失联停车时间、故障恢复 |
| 独立价值 | 可单独用于只告警和留证的安防监控 | 可使用模拟风险源独立验证嵌入式控制与安全状态机 |

强制代码边界：

- 项目 3 不复制摄像头、GStreamer、YOLOX、TensorRT、ByteTrack 或事件证据代码。
- 项目 2 只新增一个可选的实时事件输出适配器，不依赖 STM32 或 CAN。
- 实时协议同时传递风险事件与基于真实帧进度的 `PerceptionStatus`，不使用单纯
  的进程存活信号代替视频健康状态。
- 项目 3 只依赖版本化风险事件协议，不直接链接项目 2 的内部库。
- 项目 3 提供 mock risk generator 和 `vcan` 回放，离开项目 2 也能运行 CI 和控制测试。
- 两个项目分别构建、测试、发布；硬件演示时才进行系统集成。

因此，两者是“上游感知模块 + 下游控制 ECU”的组合，不是同一项目重复包装。
项目 2 证明边缘 AI 部署和持续视频系统能力；项目 3 证明 MCU、RTOS、CAN、
实时控制和软硬件故障安全能力。

## 新增技术栈

- STM32CubeIDE / CubeMX、HAL、SWD 调试和基础启动流程。
- GPIO、UART、中断、定时器、PWM、AB 相编码器和独立看门狗。
- FreeRTOS task、priority、queue、mutex、task notification 和 `FromISR` API。
- 经典 CAN 500 kbit/s、CAN ID、仲裁、错误帧、总线终端和应用协议。
- Jetson SocketCAN、`can-utils`、`vcan` 和 C++ CAN RAW socket。
- 版本、序号、心跳、超时、故障码和可选 DBC 描述。
- `NORMAL / WARNING / STOP / FAULT` 安全状态机与人工复位。
- 电机 PWM、编码器测速和可选 PI 闭环调速。
- Hardware-in-the-loop、断线、丢帧、进程崩溃和 MCU 重启故障注入。

第一版不学习 AUTOSAR、UDS、J1939、CANopen、FOC、ROS 2、Yocto、
Linux 内核驱动、自制 PCB 或功能安全认证。这些内容不得扩大第一版范围。

## 第一版验收

- 项目 2 事件源和模拟事件源都能驱动同一 Jetson CAN 网关。
- 暂停真实视频帧但保持项目 2 进程存在时，STM32 仍能按超时进入停车状态。
- CAN 双向通信、帧序号、心跳和故障码可观察。
- 正常、警告、停车、故障四种状态有确定性单元测试。
- 电机目标速度和编码器实际速度同时记录。
- 拔 CAN、杀 Jetson 进程、停止真实视频帧和复位 MCU 均有故障注入结果。
- 心跳超时后在配置时间内停止，恢复后不会自动重新启动。
- 报告事件到命令 P50/P95、CAN 往返延迟、失联停车时间和转速误差。
- 正式仓库包含接线图、演示视频、测试命令、限制和可复现实验结果。
